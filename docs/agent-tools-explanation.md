# 为什么 AI 只能提出修复，不能自己宣布正确

玩家说“这题应该回答不是”，是一个值得调查的反馈，不是标准答案。AI拿到反馈后，也可能把事实理解错。所以我们把“收集资料”“查冲突”“跑检查”“提出修改”和“正式发布”分开。

五个受控工具已具备本地实现，服务器配置与管理员权限决定后台任务是否启用。候选仍须人工审核与受控发布；真实模型质量另待验收。接口见[工具说明](agent-tools-reference.md)，当前证据与依赖见[完整范围对照](original-scope-crosswalk.md)。

## 五个工具像五张有限权限的工作单

AI可以查看这条反馈经过审核的脱敏材料、找同一题的事实、查已有规则、申请程序检查、保存待审建议。它不能翻任意玩家记录、运行系统命令、直接改数据库或自行发布。

看到一个真实事实编号，只能说明“这份资料存在”。不能说明“AI从资料推出来的答案一定正确”。因此程序不会给AI输出盖上“答案已被证明”的章。

## 安全检查和答案正确是两件事

安全检查能确定：坏格式有没有被拒绝、有没有越权、是不是重复执行、超时后是否仍乱写。这些都是可以用代码验证的事。

要判断某一句中文答案对不对，还需要独立审核的题目和标准答案。不能让AI先写答案，再用自己写的答案给自己打满分。现在缺这份合格题集时，程序保留已完成的安全检查，同时明确写“还没测完”，不生成通过验收的候选。

即使以后题集全过，也只是“在这些已审核案例上表现符合预期”，不是证明任何自然语言问题都不会错。最终人审和发布权限仍单独保留。

## 为什么先记工作单，再执行

假设程序执行到一半电脑断开，回来时不能知道刚才到底做完没有。如果把旧工作单再执行一次，却不算新尝试，就可能反复跑出结果、绕过预算。

所以先保存“准备做这件事”，占一次Agent工具尝试；确定做完后再保存结果。已完成的只重放结果，不重做。旧记录只有“准备做”而结果未知，就先标记不确定，后续由工作流判断怎么恢复。

这里说的是后台Agent的工具预算，**不是玩家提问次数**。玩家请求的失败不扣次数，与Agent失败尝试不能免费重跑，是两个不同计数器。

## 为什么计算结束还要检查一次权限

管理员可能在AI检查过程中撤回这份材料的使用许可。开始时有许可，不代表结束时仍有。程序因此在保存结果那一刻重新检查；许可撤回、任务结束或执行者身份变化，都不能偷偷保存迟到结果。

检查时不长时间占住数据库，正常玩家请求不会因为一整个后台计算一直等锁。当前这些工具没有接入每个玩家提问，也没有让普通问题一律额外跑一次安全回归。本地并发和浏览器流程已有[有限停止与恢复证据](acceptance-a51-a52.md)及[人工审核页面证据](acceptance-a54-a56.md)；实际部署性能仍需对应环境验证。

## 为什么彩蛋题先留给人工

有些题的“全部回答是”或特殊通关条件优先级高于普通问答规则。把一条修复强插在前面，可能破坏整个彩蛋。因此目前只暂停这类候选自动处理，不改玩家现有游戏流程，继续处理不受影响的普通规则。

## 这对面试意味着什么

还有一个容易忽略的问题：电脑上的代码文件更新了，已经启动的程序可能还在用内存里的旧代码。就像换了菜谱，厨师却还照旧菜谱做菜；不能拿新菜谱的编号给旧菜做出的结果签字。后台回归现在会核对实际加载的程序和文件，发生变化就要求重新启动后台进程，再做回归。这项检查只在后台修复任务里，不让玩家每次提问都多做一遍。

你可以解释自己如何限制AI权限、保留失败记录、避免自评满分，以及区分离线测试和真实质量。不能说“跑了测试，所以AI答案保证正确”，也不能把AI草案称作人工标注、把本地检查称作已上线验收。学习时对照[当前进度](autonomous-progress.md)和实际测试记录，区分已经做好的能力与后续计划。
