# TS14 dynamic repair loop design

DESIGN ONLY while sole TS13 reviewer Jason is active. No TS14 product code/tests or frozen TS13 changes until its terminal verdict/regrade/one fix/final gates. User explicitly delegated in-scope decisions and continuous execution; no phase approval, commit, new worktree or extra per-unit reviewer. Original TS14/A50–53/D2/D4/D6/D8 remain binding, real external subsets held rather than removed.

## Intent and choices

Build an actual bounded model-selected tool loop, not a fixed sequence dressed as an Agent. A model may select any permitted tool or finish; the server validates scope, owns identities/budget/lease and stores decisions/results. Safe failure, cancellation, restart and human handoff are outcomes, not demo failures to hide. Protect normal game latency by sharing the existing local model admission and yielding to online work. No paid fallback, real secrets/player reads, production activation/deploy or invented human/model evidence.

Chosen architecture: extend the existing ModelGateway with a closed SERVER-selected response contract and reuse TS13 storage/tools. Alternative separate Agent gateway would bypass the shared two-call limit and is rejected. Adding a framework/provider SDK is unnecessary for this scoped state machine and would expand dependencies and recovery semantics. No new dependency or schema004.

## Response protocol and gateway

ModelGateway.invoke retains existing host judgment default and all current cancellation/owner/cleanup rules. Add a closed response_contract host_judgment|repair_action chosen by trusted server code, never a model callback/class/import path. repair_action uses strict parse_agent_action: exactly five ToolAction variants or FinishAction, <=32KiB, no duplicate/extras/nonfinite/server identity. Invalid agent JSON maps to model_output_invalid without exposing body or underlying exception; normal host/evaluation output stays unchanged. Compatible transport remains the existing verified-free adapter. No hidden retries: the agent invokes max_attempts=1 and controls each correction/retry as a new durable attempt.

Prompts are a fixed registered asset. Input includes only frozen privacy-reviewed TaskContext, task-owned bounded steps/results and closed tool schemas; facts/feedback/tool text are data, not new authority. Max decision input 8000 characters; no silent dropping that would misrepresent earlier execution. Too-large task input becomes needs_human/context_too_large. Do not request/store raw model chain of thought. A parsed action and short stable failures are sufficient.

## Durable model intents using existing agent_steps

Extend internal stored-step union with DecisionIntent(action=model_decision, schemaVersion=1, promptDigest, inputDigest, correctionOf nullable own operationKey). This is NOT a public model action: parse_agent_action continues to reject model_decision. StepRecord can store this internal intent alongside tools/finish; replace every implicit .tool assumption with a closed type check. No migration003 SQL/checksum edits: bounded action_json/result_json already store versioned objects.

Add AgentStore.reserve_decision(identity, *, prompt_digest, input_digest, correction_of=None) returning atomic StepReservation; reserve one of the original ten model attempts and immutable intent in the same transaction before gateway invocation. The counter is conservative local attempted/reserved work, not provider receipt/token evidence; an admission failure or uncertain interrupted call does not refund it. Same completed result is replayed after permission/owner checks; an old planned decision cannot re-call under the old reservation. A genuinely new call gets new operationKey/seq and consumes the remainder.

DecisionResult(schemaVersion=1, status=valid|invalid|unavailable|cancelled, action nullable typed AgentAction, stable errorCode nullable, inputDigest/promptDigest) records the actual result, never raw provider output. AgentStore.complete_decision revalidates own planned identity/input digests/current lease/context and atomically saves result/audit. Non-valid outcomes must have no action; valid must have one. Invalid output correction stays within one logical episode via persisted correctionOf/key digest, never keyed solely by different invalid raw text. The single correction and all tool retries consume global budgets.

## Budget, loop and replay

Existing checkpoint policy remains 10 model attempts, 8 tool attempts, original180 seconds, real integer counters, RetryCounts max one per model episode or same canonical tool action. Tool scope/schema refusal is not executed work (TS13 reserves nothing); do not retry authority violations. Actual failed tools retain their reserved attempt; at most one retry with new execution identity and durable retry counter. No implicit while retry or resetting the original UTC deadline after restart/renewal.

RepairAgent(store, executor, gateway) requires exact owned dependencies. drive(run_id, lease_token, cancelled) reads owned completed steps into bounded prompt history, reserves/executes a decision, completes it, then dispatches the model's chosen validated tool or guarded finish. There is no product sequence such as always retrieve->test->save. Repeat decisions/tools are allowed only under the fixed limits; repeated uncertain intent, absent compatible corpus, insufficient evidence, authority violation, budget/deadline exhaustion or unrecoverable model/tool failure stops clearly. Successful finish(candidateId) only awaits human review; finish(needsHumanReason) stops without a publish action.

At every boundary re-read current owner/context. A heartbeat incrementing rowVersion under the same token is legitimate; do not require pre-compute version equality. A changed/expired token, withdrawn model permission or changed source cannot save a late decision/report/candidate or start another step. The gateway keeps actual owner capacity until its thread and transport cleanup are confirmed; response timeout/stop does not imply remote cancellation. Unknown cleanup prevents subsequent task model work, not a fabricated success.

## Stop and status paths

Add a terminal-only AgentStore.stop(run_id, *, lease_token, state, reason) for server failed|needs_human, and admin cancel(run_id, *, expected_row_version). These do not create source/model/tool work or approval; only remove authority. Read raw bounded RunRecord rather than require revoked _freeze permission to succeed, otherwise a task cannot record that permission was withdrawn. Check current lease/token/state/CAS; stale owners cannot stop a new owner's run. An expired original deadline can be stopped by the still-current owner, never restarted. Immutable manifests and counters remain intact, terminal clears lease. Stable closed reasons and typed audit, no raw exceptions.

AgentStore.read_status(run_id) is an admin-consumed minimal DTO: ids/state/counters/deadline/stable stop reason/candidate identity and bounded safe step summary. It can show stopped status after model permission withdrawal without exposing raw task manifest/player trace/tool text. Model-facing reads still re-freeze permission. Current malformed/corrupt record returns controlled unavailable, never fabricates valid source.

Ruling: invalid legacy feedback cannot create a fake TaskContext/run just to provide a runId. Preserve feedback; creation returns controlled missing_trace/needs-human refusal with no started task. An explicitly authorized synthetic reproduction would be a separate marked source, never real success evidence.

## Worker, leases and lifecycle

Terminal reason persistence uses an internal immutable StopIntent/StopResult step in the same transaction, with server-generated operationKey/nextseq: existing run/checkpoint fields have no stop-reason column. Do not insert unknown checkpoint keys or edit003. StopReason is a closed enum: source_changed, permission_revoked, budget_exhausted, deadline, model_output_invalid, tool_failed, model_unavailable, cancellation, shutting_down, missing_corpus, context_too_large. The human-readable detail stays generic and does not contain model/private text.

Recovery links a completed model decision to its immediately following typed tool/finish step in contiguous server sequence; compare canonical action identity, not a model-supplied execution key. Replay finished steps without new reservations. Uncertain planned tool/decision work can use a new operation/sequence and the same persisted logical retry parent under its one-retry/global/original-deadline limits; never free-reexecute the old reservation. A last permitted decision may still finish or consume an available tool slot; exhausted budget only blocks NEW attempts, not already stored safe outcomes. Failed middle context never becomes a valid assistant answer in the next prompt.

One app-local stoppable coordinator and at most one running agent task; durable queue limit10 is TS13's SQLite source of truth, not PendingAgentQueue RAM as a second scheduler. Queued task is not claimed while current shared gateway is busy/has waiting online callers or unsafe cleanup. Snapshot is advisory: a later admission race still obeys the gateway's atomic priority/capacity rules. Claim is first execution start; later waiting counts in the original180 seconds. Single-worker ENABLE_AGENT guard already exists, retain it; normal default remains disabled.

Original audit specifies worker lease60 seconds/heartbeat10. TS13 standalone primitives currently lease30; TS14 will preserve their existing default and introduce a closed SERVER-only lease_seconds=30|60 setting, worker selects60, with native tests for both and original deadline clamp. Model/HTTP args cannot change it. Heartbeat is independent of blocking drive/model invocation; one stoppable Event-based timer, not unlimited per-step threads. Lost heartbeat/lease cancels current work and denies further commits; do not renew cancelled/terminal/expired tasks. Awaiting_review ends heartbeat and model work; human reading is not limited to180 seconds.

Shutdown first denies new claims/model work, signals task/heartbeat stop, then performs bounded owned gateway/worker cleanup. Existing Runtime closed flag protects gateway creation/shutdown races. Terminal-only persistence may be allowed during close through an internal stop-only path, not a general allow_closed bypass for tool/decision writes. Report active/timed_out_but_running/cleanup_failed and bounded worker join honestly; do not kill native threads/shared transports or announce remote inference termination. Unfinished durable reservation stays for conservative restart recovery.

## Admin API and activation

TS14 adds only admin start/status/cancel routes under /api/feedback/admin/agent-runs. StrictJSONRoute, configured admin auth/rate limits/32KiB input; no role/traffic/tool/model/lease fields supplied by callers. Start body feedbackId/requestId/expectedFeedbackVersion; create idempotency returns same own run on same input and409 changed body. Status has bounded minimal DTO, cancel requires current row version. No approve/publish endpoint (TS15).

Default ENABLE_AGENT=false and app initialize002 stay unchanged. Enabling requires explicit003 and one API worker plus owned worker/gateway configuration; no auto migration or production setting changes. Tests explicitly enable on owned synthetic003/FakeActionModel instances. Real provider eligibility unknown/unverified/unavailable or payment risk must stop/wait with no paid fallback. No actual cloud calls/credential reads in autonomous local implementation.
