# TS-07 typed confirmed coverage and honest reveal

Architectural continuation of approved TS-07/A26–A29/C05/C10/C12. Human intent: playable real-user AI application, zero-new-payment, transparent recruiting evidence; do not confuse model failures with ordinary semantic uncertainty or claim a player understood a story merely because a word was mentioned. Human explicit local autonomy/no stage prompts replaces approval menus with recorded self-review, not production/private-data/model/public-upload authority. TS06 review is active; this is disjoint planning only.

## Selected approach and alternatives

Use committed typed turns, source-bound proposition matching and a focused pure scorer, retain the existing transactional one-time reveal. This has deterministic tests and no extra model latency. Fixing only answer-prefix comparisons would leave negative/subject/quantity/topic collisions and multiline text forging. A model-based reconstruction judge would need unapproved calls, independent evidence and reliability work, so it is not the first version. Do not introduce another schema migration or mutate immutable Soup/p1/r1 payloads.

## What the scores mean

New evaluations: completion equals verifiedCoverage, the percent of known boolean checkpoint propositions actually confirmed by eligible recorded answers. This is host-confirmed source coverage, not independent model accuracy or player reconstruction. Unknown checkpoints are reported separately, never in the known-fact denominator. No known facts gives coverage 0 with an explicit '没有可确认的计分要点' explanation, not a perfect score.

reconstructionScore is always null in this version: no independent reconstruction evaluator exists. UI says '还原程度：尚未独立评估'. A typed binary host answer can confirm its exact supported proposition; 是也不是/算是/与此无关, system_error, reminder, invalid/unpaired legacy messages and pasted free-form reasoning do not become full fact confirmation. A failed/free row cannot prove anything merely because its text contains a keyword.

Confirmation needs both a complete question-to-checkpoint relation and strict actual answer agreement. Use TS06's supported subject/predicate grammar/complete safe authored aliases; negation, different subject, counts/times/conditions and uncovered clauses must not collapse. Binary polarity is compared against the expected answer to that specific full question (so a correctly answered negative question can confirm a positive fact); never compare a negated question to an unrelated bare word. Unsupported paraphrase earns no fact coverage, even if it received a legitimate model answer. This conservative measurement may undercount real understanding; it is not a game-question refusal or a quality claim.

Whole/all-clause deterministic decisions may contribute multiple facts only when each fact is supported by the actual pinned checkpoint source and the complete decision is binary and agrees with the committed answer. Partial compound answers do not count as full confirmation. LLM branch does not get automatic authority from a display marker or an evidence-looking string; each counted proposition must be independently matched to a known pinned source. Record distinct checkpoint identities, count a fact at most once; duplicate topics/aliases do not create new facts. Existing duplicate authored checkpoints remain distinct source records, not silently deduplicated schema changes.

## Authoritative input and legacy compatibility

Introduce frozen ConfirmedTurn(question, result:HostResult, turnId, history) for pure scoring input, using complete prior valid turns for scope/reference guards. Actual server scoring reads completed charged turn rows/results bound to that session and pinned p1/r1/engine, not a plaintext concatenation of '玩家：/主持人：' messages. Embedded/newlines in user text cannot invent a host row. Exclude failed/reserved/expired/reminder; handle an actual committed win separately. Revalidate saved HostResult using existing strict JSON/version/source identity boundaries; corruption is a safe refusal, not a guessed score or silently ignored evidence gap.

Pre-001 migrated compatible pairs may lack typed result/turn IDs. Do not fabricate a result/evidence or convert decorative reply prefixes to a canonical answer. Preserve their history; they are unverified legacy evidence and contribute zero in the new conservative scorer unless an existing real typed turn is present. Explain exclusions using aggregate counts, not public session IDs or internal source payloads. No production migration is authorized.

Already saved evaluation bodies are immutable one-time results: retain their original body/score version and do not recalculate or rewrite them. Append-only evaluation DTO fields have safe legacy defaults: verifiedCoverage=null, reconstructionScore=null, scoreVersion=null, plotProgress=null and unknownTopics=[], while new bodies explicitly provide coverage-v1 and numeric verifiedCoverage. Legacy UI labels completion '历史分数（旧口径）', never relabels it verified. Strict validation checks new relationships only when scoreVersion is coverage-v1; absence is a marked legacy result, not newly verified evidence.

## Narrative rules remain separate

Keep difficulty fallback, hidden/unlimited/always_yes, actual win state and unlock behavior. The existing special_scoring compatibility mapping is a narrative unlock policy, not the factual coverage algorithm. Evaluate it separately into plotProgress only for opted-in special_scoring, using eligible complete typed five-class answers and the existing thematic configuration. Preserve its >=50 raw thematic progress → >=70 plot mapping/70 unlock boundary as fiction/game behavior; never copy that number into completion/verifiedCoverage or ordinary model-quality metrics. Label it '剧情进度（非还原评分）'. Irrelevant/error/free or absent eligible answers cannot manufacture positive thematic progress; stricter factual confirmation remains independent.

A real committed kind=win yields plotProgress=100 and preserves solved/isWin/isReveal behavior; it does not force factual coverage or reconstruction to 100. Merely mentioning win keywords in an error/free/unpaired input is not a committed win. If legacy tests equate plot success with factual completion=100, preserve their actual game status and dedicated plot assertion, replace only the disproved metric equivalence with a recorded counterexample/ruling. Special scoring remains excluded from later ordinary quality metrics.

## Integration and UI

Replace ai_host.evaluate_completion internals with a narrow compatibility adapter to the focused scorer; public production reveal uses typed inputs, no plaintext parsing authority. Keep old pure CLI/test signature only as explicitly legacy/unverified input, not a parallel online score engine. game_service supplies pinned source/typed turns; game_store.evaluate_once stays one short transaction and freezes full new EvaluationResult. In-flight 409, solved not given_up, repeated reveal no extra model/state changes and ended recovery are preserved.

Progress hints are also a scorer consumer: do not silently make every active game's progress zero. Supply a separate private host-history view with the actual typed result for each matched turn; don't append private result/evidence to public session DTO messages. Read its messages/results under one consistent read transaction with source pins checked, just as the TS04 public view avoids mixed snapshots. Current reserved/failed/free rows remain nonfactual. The same pure scorer serves progress and reveal, without showing checkpoint keys in an ongoing hint; pure unverified legacy callers get an explicit conservative explanation instead of guessed coverage.

Add fields to EvaluationResult only, not Soup or baseline rule fields/checksums. Names: verifiedCoverage (integer 0..100 or legacy null), reconstructionScore (null), scoreVersion ('coverage-v1' or legacy null), plotProgress (integer 0..100 or null), unknownTopics (list of checkpoint display keys). Covered/missing known facts still use keyPointsCovered/keyPointsMissing and remain legal reveal data. Bind score engine identity in new saved result, not an in-place baseline schema patch.

Minimal game-page/API result types and labels show confirmed coverage, null reconstruction and separate narrative progress; don't implement TS08's state machine/recovery in this stage. Before any Next edit, main reads relevant installed node_modules/next/dist/docs guides as repo AGENTS requires. Old-result fallback is explicit and tested. No full redesign/production/browser network. UI verification uses isolated local fixtures only; API-only Playwright is not falsely called UI coverage.
