## Architecture decision and alternatives

Use a small private candidate review store, strict admin HTTP and focused admin panel; reuse SQLite runtime_meta CAS/operation receipts and existing RulePublisher. Candidate/step/release bodies remain immutable. A trusted optional FrozenDataset factory input connects the existing single-corpus FixedRegression to loop AND human review; no auto-discovery or model/browser paths. This supports the existing one-catalog pilot contract, not a claim of autonomous repairs for all soups.

Rejected alternatives: browser-generated ReviewReceipt/ChangeDraft would bypass server binding; modifying immutable003 or inventing review_json/row_version columns breaks released-migration safety. Do not introduce services/queues or a paid semanticjudge. A future corpus registry/multipleAPIworkers is separate work requiring measurement, not quietly included.

### Request fields (no caller-provided authority)

- CandidateApprove: operationKey, expectedReviewVersion, expectedProofDigest, answerSupported=true, contextIndependent=true, reviewNote.
- CandidateReject: operationKey, expectedReviewVersion, reviewNote. It can dismiss stale materials without exposing/re-authorizing them; pending orapproved only, not published/rejected mutation.
- CandidatePublish: operationKey, expectedReviewVersion, expectedProofDigest, expectedRuleVersion, expectedPointerVersion. Candidate/path supplies ID; server derives every draft/receipt/report field.
- CandidateRollback: existing RollbackRequest shape operationKey/targetRuleVersion/expectedRuleVersion/expectedPointerVersion/reason/blockRuleVersion(optional). Only independentlyauthenticatedadmin, verified003/currentCAS; no modelcapability.

CandidateOperationResult is a minimal immutable acknowledgement: schemaVersion1, candidateId, operationKey, action approved|rejected|published, reviewVersion, candidateStatus approved|rejected|published, publishedRuleVersion nullable. It is the result of THAToperation, not necessarily latestpointer/state; UI subsequently refreshes detail/list before offering anothermutation.
