## 一句话讲项目

玩家向AI海龟汤主持人提问，系统保存整轮结果并支持断网恢复；玩家指出疑似错答后，管理员先核对来源并脱敏授权，Agent用有限工具寻找依据、检查候选和保存待审核建议。**人工批准、实际发布和规则回滚分别执行**，模型不能自己改线上答案。

当前能证明的是程序流程和失败边界，不是AI永远答对。随意文本被拒绝，是“格式不合格”；合法的“是”也可能语义答错，仍需要可信事实、独立评测和人工核对。失败不扣玩家游戏次数，不等于供应商调用没有消耗。

## 两条链路，两个权限边界

```text
玩家页面 + 请求记录
  -> FastAPI校验 / 来源限流
  -> SQLite登记本轮请求
  -> 规则 / 提醒 / 有界证据与模型网关（不持数据库事务等模型）
  -> SQLite一次提交结果、消息、计次与必要审计
  -> 页面显示 / 按原请求编号恢复

实际完整轮次反馈
  -> 管理员反馈审核 + 另行脱敏授权
  -> 持久化Agent任务 / 租约 / 尝试预算
  -> 模型选择白名单工具或finish
  -> 当前任务报告 + pending候选
  -> 人工核对事实与原前文 -> 批准（不发布）
  -> 单独发布 -> 新会话固定新规则版本
  -> 规则指针回退（旧局、新局和历史记录不被删掉）
```

一次请求重复送来，不应做第二遍：这是幂等。相同编号且内容一致取原结果，换内容冲突；同样文字用新编号仍是玩家主动再问。旧局固定创建时的版本，发布/回滚不偷偷改写它的历史答案。
