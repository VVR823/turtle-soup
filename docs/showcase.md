# Turtle Soup · 项目展示

玩家通过提问还原隐藏故事，系统提供规则与模型结合的 AI 主持、对局恢复和反馈审核。适合围绕 AI 应用开发与 Python 后端工程展示。

[在线演示](http://47.97.33.174/) · [简历稿](../RESUME.md) · [实现证据](resume-evidence.md)

网站保留访问口令，现场由项目所有者输入。当前部署记录见 [2026-10-25 发布](deployment-2026-10-25.md)。

## 五分钟演示

1. **开始一局**：选择题目与难度，提交一次问题，展示回答和剩余次数。
2. **解释请求恢复**：结合 [恢复测试](../backend/tests/test_game_request_recovery.py)说明重复请求如何取回原结果、避免重复计次。
3. **查看玩家反馈**：展示管理页如何查看原问答、审核反馈和查询历史。
4. **说明规则发布**：结合 [隔离浏览器流程](../tests/ui/admin-agent-review.spec.ts)讲解候选、批准、发布和回滚；生产自动 Agent 当前关闭。
5. **说明上线维护**：用 [发布记录](deployment-2026-10-25.md)展示独立数据目录、备份与旧版本保留。

演示使用已有材料；涉及恢复、发布和回滚的操作在隔离环境展示，真实玩家数据保持原状。

## 三个值得展开的设计

| 问题 | 实现方式 | 阅读入口 |
| --- | --- | --- |
| 断网后重试，怎样避免再扣一次次数？ | 原请求编号、唯一约束、整轮事务提交 | [业务处理](../backend/app/game_service.py)、[恢复原理](game-recovery.md) |
| 怎样减少主持人随意回答？ | 来源绑定规则、题目事实与证据、限定输出合同 | [主持逻辑](../backend/app/ai_host.py)、[输出测试](../backend/tests/test_host_contract.py) |
| AI 建议怎样安全变成正式规则？ | 受限工具生成候选，人工批准、单独发布，按会话固定版本 | [修复 Agent](../backend/app/agents/repair_agent.py)、[候选审核](candidate-review-reference.md) |

模型输出格式合法并不保证答案正确。质量数字的适用范围见 [证据表](resume-evidence.md)，生产配置和历史测试结果以对应记录为准。

## 贡献与面试准备

项目所有者负责需求定义、体验迭代与验收，工程实现和测试采用 AI 辅助协作。面试时围绕本人能解释、复现的部分展开：一次提问的完整流程、事务与重试、规则版本、人工发布和数据恢复。

详细阅读顺序见 [学习路线](learning/project-learning-map.md)。阶段展示稿及早期证据已移至 [历史归档](archive/README.md)。
