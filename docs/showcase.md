# Turtle Soup · 项目展示

这是一个自己提问、自己盘故事的海龟汤网站。玩家选题后向主持人提问，主持人根据题目事实作答。项目包含 65 道公开汤，以及对局存档、难度选择和错答反馈。

[在线演示](http://47.97.33.174/) · [简历稿](../RESUME.md) · [实现证据](resume-evidence.md)

网站保留访问口令，现场由项目所有者输入。当前部署记录见 [2026-10-25 发布](deployment-2026-10-25.md)。

## 提问与断网恢复

页面发送问题时附带请求编号。后端先查这次请求是否已经处理，再进行规则或模型判断，最后把回答、消息和提问次数一起写入数据库。

如果回答已经保存、页面却因断网没有收到，重试时仍使用原编号取回结果，避免再次扣次数。实现见 [业务处理](../backend/app/game_service.py)，具体场景见 [恢复测试](../backend/tests/test_game_request_recovery.py)。

## 错答反馈与规则更新

模型可能答错，玩家可以反馈。管理员核对原问题和前文后，才决定如何处理；反馈本身不会直接变成正式答案。

修复 Agent 使用受限工具生成候选规则，批准和发布是两步操作。发布后新开的局使用新规则，旧局保留原版本。生产自动 Agent 目前关闭，流程演示使用 [隔离测试材料](../tests/ui/admin-agent-review.spec.ts)；接口见 [候选审核说明](candidate-review-reference.md)。

## 上线与维护

服务通过 Nginx 和 systemd 运行。程序按版本保存，运行数据单独存放，发布时保留数据库备份和旧版本。部署及恢复记录见 [发布记录](deployment-2026-10-25.md)。

质量数字、测试版本和适用范围集中放在 [证据表](resume-evidence.md)，便于按需复核。

## 贡献与面试准备

项目所有者负责需求定义、体验迭代与验收，前端由 AI 辅助实现，后端和测试也有 AI 协作。技术讲解围绕本人能解释、复现的工作展开。

现场可先玩一局，再展示一条反馈，最后结合源码讲请求恢复或规则发布。涉及数据恢复、发布和回滚的操作在隔离环境演示。
