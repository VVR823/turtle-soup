# 修复 Agent 到底做什么？

它像一个有权限限制的“售后分析员”，不是直接给玩家主持游戏的 AI。玩家正常提问仍走原来的主持链；管理员确认一条反馈及隐私许可后，修复 Agent 才分析它。技术细节见[接口参考](agent-loop-reference.md)，证据边界见[TS14状态](ts14-status.md)。

## 不是固定脚本，也不是随便执行命令

```text
管理员批准材料 → 保存排队任务 → 单任务 worker + 独立心跳
                                ↓
                  模型选下一动作 → 服务器检查 → 五个限定工具
                                ↑                    ↓
                                └──── 实际结果 ──────┘
                              停止 / 待人工审核候选
```

模型可以决定先看回合记录、查事实、检查冲突、跑回归、存候选，或直接请求人接手，所以不是固定的“查一次资料→输出答案”流水线。但它只能在服务器给的五个按钮里选，不能运行 Python、SQL、命令行、访问任意文件，或自己加权限。

“模型返回格式正确”只说明它按按钮的格式填写了参数，**不说明判断正确**。比如它写了合法 JSON，却把“丈夫”理解成“父亲”，格式检查抓不到这种语义错误。必须结合来源事实、反例、独立题集和人工审核；不能让模型自己给自己判满分。

## 为什么先记账，再做事？

假设模型开始调用后电脑断线了。只记最终成功，恢复时就会把这次当“没发生”，无限重试，还无法知道是不是重复扣了外部额度。因此先保存“准备尝试”，再保存结果。失败记失败，不清楚就保留“不确定”，不编造成功。

一项修复最多10次模型尝试、8次工具尝试、从首次领取算180秒。断点恢复用剩下的次数和原期限：用了9次模型、7次工具，恢复后只剩各1次，不能重新送一整套预算。这里数的是服务器预留尝试，**不是已证实的供应商扣费次数**。没有供应商证据就标未知。

这和玩家次数是两本账：玩家那边，模型技术失败不能算成有效答案、不能扣提问次数；后台修复这边，已经尝试的失败不能把工作预算退掉。目的分别是保护玩家体验，以及避免后台无限循环。

## 心跳与取消：谁现在有资格写结果？

worker 领取任务后拿一个临时“工作证”（租约），每10秒续一次。模型卡住时另一个心跳线程仍可续证；它只续证，不额外调用模型。取消、撤权、材料改版或另一 worker 接管后，旧工作证不能把迟到的结果写回来。

任务摘要和实际运行材料是两种权限。管理员可以在材料撤回后看“已取消、尝试几次”这种最小摘要，不代表 AI 又获得阅读原文的权限。取消版本冲突时重新读状态，也不能强行盖过别人的更新。

心跳失败也一样：虽然原“工作证”还没到期，这次执行已经失去交结果的资格。正在计算的结果不能写成成功，原先预留的次数仍保留。关闭电脑上的服务时，数据库写入即使先排队、后来才拿到锁，也必须重新检查，不能凭排队前的许可偷偷提交。

还没开工的任务若材料已撤回或改版，会自动转为“需要人工处理”，释放排队名额；不把这段等待算进180秒，也不调用模型。已经预留模型次数、但真正发请求前撤权，则阻止发送并保留预留记录，不声称撤回了已经发出的云端请求。

## 为什么“全部回归通过”还不能上线？

回归像做练习题：失败题、没做完的题都要保留在总数里。如果没有独立题集，或者清理状态不确定，就不能当成“全过”。即使通过，也可能只是这套题没有覆盖到某个中文歧义。

所以 Agent 保存的候选只能是 `pending`，任务只能到 `awaiting_review`。管理员的人工审核与受控发布已实现：先核对事实、明确确认答案和上下文独立性并写理由，再提交绑定原报告的批准；发布时还会重新检查材料和版本。批准与发布是两个操作，Agent不能代替管理员执行。修复 Agent 不会在玩家随便问一句时自动启动，也不会因后台生成候选就改动生效规则。审核与发布流程见[人工审核证据](acceptance-a54-a56.md)。

测试里的8条完整模拟任务能证明预算、取消、恢复、失败留痕等工程行为，但没有使用真实云模型，也没有真人给8条反馈下标准结论。它们不能宣传为“8条真实问题已自动修复”。

## 已知取舍

先采用单进程/单worker和SQLite，降低学生项目的运维与付费成本；这不是无限吞吐架构。模型网关给在线玩家优先级，但不能承诺后台绝不影响延迟，真实压力与部署还需验收。清理未知时保守占住名额可能降低可用性，比把仍可能在运行的调用当已结束更可解释。

8000字符放不下完整记录时转人工，不偷偷删反例。零新增付费是实施约束，不是“任何供应商永远免费”或“无需提高模型品质”。真实接线、免费资格与人工独立答案仍单独待定。
